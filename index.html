A debugger that knows IOS

Every line is checked as you type. Problem lines are underlined in the editor, and the debugger lists each issue. Pick one to see why it's a problem.

  • Invalid values, like an NTP server of 10.20.30.999 or a static route to a next hop of 10.20.400.1
  • Settings IOS would reject, like a spanning-tree priority of 4097
  • Overlapping subnets, like a VLAN interface that overlaps the management network
  • Open STIG findings on their own Compliance tab, next to the problems

Routing builders: OSPF, EIGRP and BGP

Every part of the config has a form, listed down the left with its status. Shown here: BGP on an edge switch with an ISP neighbor and an iBGP peer.

  • Neighbors with their remote AS, description and update source, and switches for activate, next-hop-self and shutdown
  • Networks to advertise, one row each
  • Lines the form doesn't show, like a neighbor's password or route map, kept exactly as written
  • Plain-language help on every card, like which neighbors are iBGP and which are eBGP

ACLs without the guesswork

Deploy

Every commit has a way back

Safe Commit sends only the lines that changed. Every commit, from the editor, a drift fix, Bulk or the MAC finder, goes through the same approval, recovery point and command-by-command checks. A backup and a before/after check are on by default, except for quick port fixes from the MAC finder.

Pre-flight

The switch is reachable, and any command that could cut off management access is flagged. For changes from the editor, the commit stops if the switch isn't the one you read or has changed since, and debugger errors and STIG or golden-standard regressions are flagged before you approve.

Change

You approve the exact commands, and risky ones need the hostname typed. A backup and a recovery point (a flash copy, or a checkpoint on NX-OS) come first, then on IOS and IOS XE a reload-in-10 safety net. Commands go one at a time and stop at the first one the switch refuses.

Post-check

Still reachable, every command accepted, and before/after compared: ports, err-disabled, CDP neighbors, MAC learning, the spanning-tree root, and OSPF, EIGRP and BGP neighbors. A failed check offers a rollback, confirmed by reading the config back.

These safeguards are tested against a simulated switch so far. Try them on a lab switch first, and tell us how it went.

Built for secure environments

Runs on one Windows PC. No cloud, no sign-up.

Backups, project files and saved passwords are encrypted for your Windows account. It connects only to the switches you name and the CDP and LLDP neighbors that topology discovery finds, plus Cisco's advisory service if you turn it on.

FIPS mode

SSH uses approved algorithms only, host keys are confirmed before they're trusted, Telnet is off, and TFTP needs your OK each time and is logged.

Air-gap ready

Licenses are checked on the PC, so the app works on networks with no internet at all. No telemetry and no update checks.

SBOM and checksums

Every release ships a CycloneDX software bill of materials listing exactly what the exe contains, and SHA-256 checksums.

Admin and read-only profiles

Auditors and IT viewers get a read-only profile that SwitchForge won't let edit configs, apply fixes, commit or push. What anyone can type on a switch is still up to its own AAA.

Audit trail

A changelog of every edit, commit and export, and a saved record of each deployment with secrets removed.

Encryption and secrets

Backups and project files are encrypted for your Windows user. New local accounts and the enable secret are hashed as type 9 (type 8 in FIPS mode), and secrets are masked in evidence, records and the change log.

FAQ

Questions testers ask

Do I need a switch to try it?

No. Design, the builders, the debugger, the STIG checks and reports all work offline, on the built-in sample switch or a config file you import. Connect to a switch when you want to read its config or deploy.

Which STIGs does it check?

The Cisco IOS and IOS XE switch STIGs (L2S and NDM) and the router STIG are checked rule by rule. NX-OS STIGs are checked too, but more of their rules are left for you to review, and those checks are less tested so far. Load the STIG from DISA's download, an XCCDF file or a STIG Viewer checklist.

Does it need internet access?

No. The license is checked on the PC, and a starter set of Cisco advisory and end-of-life data is bundled; you can import a newer data file. The only outside connection is the optional online advisory check on the Versions page, which uses your own Cisco API key.

Is it FIPS 140 validated?

No. SwitchForge isn't a validated module and hasn't been through CMVP testing. In FIPS mode it uses only FIPS-approved algorithms: its own encryption goes through Windows CNG, the module covered by Microsoft's FIPS 140 validations, and SSH is limited to approved algorithms, although the SSH library in these test builds isn't itself a validated module.

Is it code-signed?

Not yet; signing is being set up. Until then SmartScreen will warn you, and a PC that only runs signed apps may block it. Check the file against SHA256SUMS.txt from the same release.

Where is my data kept?

Backups, settings and the changelog are kept in your Windows profile, under %AppData%\SwitchForge. Projects are saved wherever you choose. Backups, project files and remembered session passwords are encrypted with Windows DPAPI, so only your Windows account can open them. To move a project to another PC, use File > Save portable copy. Nothing is uploaded.

What does read-only mean?

Without a valid license, or on a read-only profile, you can open projects and look around, but SwitchForge won't let you change configs or push to switches. A tester license lasts 30 days, and when it runs out your projects and backups stay where they are.

How do I report a problem?

Through the contact you received your invitation from. Include the version number (in the main window's title bar, like SwitchForge 0.7.0) and what you were doing.
